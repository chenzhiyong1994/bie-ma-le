# 2026-07-17：四角色共用质量校准报告协议

## 背景

首个可运行版本只服务现称“简历暴君”的简历角色，报告默认把所有材料当作需要重刑批判的差简历。面对本身质量较高的独立材料时，系统仍倾向只找负面问题；长材料命中大量低质量表述时，单条证据卡又无法表达“这是一个反复出现的模式”。继续为每个新场景复制提示词、接口字段和页面会让角色质量与产品行为逐渐分叉。

## 决定

1. 公开切片先支持四个角色：简历暴君、汇报暴君、文案暴君、产品暴君。
2. 四个角色通过注册表配置专业身份、目标背景、四项诊断维度和表达示例，共用同一评审引擎、API、报告结构和安全协议。
3. 报告按总分分为 `critical`（0-49）、`rebuilding`（50-79）和 `ready`（80-100）。材料越成熟，反馈越偏向确认已成立的优势和边际改进；`ready` 允许零问题，不强制受控嘲讽。
4. 正面结论与负面结论都必须引用材料中的精确证据。`strengths` 是一等输出，不再只把肯定塞进总评。
5. 一个问题可聚合 1-8 段同类证据，表达“同一种缺陷反复发生”；问题数量仍限制为 0-3 个，避免把长材料拆成无穷清单。
6. API 统一使用 `materialText` 和 `contextText`。旧版简历字段只作临时兼容，新功能不继续依赖。

## 理由

- 质量分层避免把“暴君感”误解成无条件否定，提高不同质量材料判断的可信度。
- 优势同样要求证据，使正面批判不是空泛鼓励，也能告诉用户哪些内容不应在修改时误删。
- 证据聚类在保持三项优先级上限的同时适配长材料，用户能看到问题的覆盖面和重复频率。
- 角色注册表把专业差异放在配置中，新增角色不再复制 API、任务状态机和页面逻辑。

## 替代方案

- 保持纯负面报告：实现最简单，但高质量材料会被迫挑错，产品判断失去可信度。
- 每个证据生成一张问题卡：定位精确，但长材料会形成几十张卡片，用户无法判断优先级。
- 为每个角色建立独立接口与页面：短期直观，长期会产生协议、安全和交互分叉。

## 影响与边界

- 客户端需要按质量层展示红、琥珀、绿三种报告状态，并提供宽卡片与证据展开。
- 评测集必须覆盖每个角色的差、中、优材料，以及提示词注入等边界情况。
- `critical` 仍需保持直接、高压、证据化的表达；质量校准不是新增用户侧“温柔模式”。
- 本决定不包含历史记录、问题补证、修改版对比或支付能力；2026-07-17 后前三项进一步被明确排除在一次性产品路径之外。
