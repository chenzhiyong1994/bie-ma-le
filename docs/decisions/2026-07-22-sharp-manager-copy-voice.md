# 公开语气改为尖酸刻薄的直属领导

状态：语气方向继续采用；其中狠词数量和隐喻风格硬校验已被 [2026-07-27：表达风格退出报告硬校验](2026-07-27-style-is-not-a-validation-gate.md) 取代

## 背景

首版“暴君治下验收”统一了角色世界观，也排除了刀、追债和验尸等混杂隐喻，但大量使用“呈上、案前、批示、准予”等词后，界面和模型输出更像古装公文或固定模板。用户要的是接地气的真人压迫感：一个见过太多烂材料、说话刻薄、会当面拆穿自我感动的领导。

## 决定

1. 四个公开暴君统一扮演“尖酸刻薄、不留情面的直属领导”，场景是一场真实工作评审，不是古装官署。
2. 主要语言手段改为职场反问、冷嘲和短命令，例如“这也叫成果？”“然后呢？”“拿什么证明？”“别拿过程糊弄我”。
3. `critical` 材料的每个 P0 问题先用一句短促挖苦点破，再给证据、影响、修改命令和验收标准；全篇仍只使用 1-2 处证据绑定的作品级狠词，避免靠堆脏话制造力度。
4. `rebuilding` 允许一句带刺认可，但不能抹掉已经成立的硬货；`ready` 不强塞狠词，可以用不耐烦但具体的方式承认材料能交。
5. 嘲讽对象只能是材料、写法、决策和可改变的工作行为。禁止攻击用户的智力、人格、亲属、身份特征或整体人类价值。
6. “暴君批示”保留为结果页品牌名；交互按钮和正文少用“呈上、案前、准予”等古装或公文词。
7. 不增加用户侧语气强度开关，真实 AI、固定样例、页面状态和分享文案使用同一套语气规则。

## 理由

刻薄感来自准确命中工作里的虚词、过程冒充结果和自我感动，而不是来自无差别辱骂。把嘲讽和证据、修改动作绑在一起，既能提高真人感和传播辨识度，也能守住产品的专业价值与安全边界。

## 影响

首页、角色详情、材料提交、处理状态、报告、分享文案、角色配置和 AI 系统提示词同步调整。结构化报告协议、角色 ID、云开发接口和隐私链路不变。
