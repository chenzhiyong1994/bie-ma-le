# 使用微信云开发承载生产文件与 AI 评审

日期：2026-07-20

## 决策

小程序生产运行时改用同一微信云开发环境：

1. 小程序通过 `wx.cloud.uploadFile` 临时上传 PDF/DOCX。
2. Node.js 20.19 的 `bml-api-v2` 云函数下载文件，在内存中解析文字，并无论成功失败都立即删除云存储文件。
3. 云函数通过服务端 `@cloudbase/node-sdk` 调用环境内已启用的云开发 AI 模型与云存储。
4. 既有报告 Schema、证据校验、质量分档和安全校验继续在服务端执行。
5. 材料、报告和任务不写数据库；数据库能力留待有明确持久化产品需求时再启用。
6. CloudBase 会保留云函数事件和返回值，因此正文、目标背景和报告通过临时私有云存储 JSON 交换；事件和返回值只携带随机 `fileID`，输入和输出分别在消费后立即删除。

该决策取代 2026-07-15 的第三方 AI 传输作为生产默认。原本的 Node HTTP API 仅保留为本地测试适配器，不再被小程序调用。

## 原因

- 真机不能访问 `127.0.0.1`，云开发原生调用无需自建公网 API 或配置业务域名。
- 云函数可使用环境临时凭证访问套餐内 AI，不把密钥放进小程序。
- 临时云存储解决真实文件上传，同时保留“用完即走”和最小化持久化边界。
- 保留服务端报告校验，避免把模型原始输出直接展示给用户。

## 边界

- 当前只支持可提取文本的 PDF 和 DOCX，8 MB 上限；不做 OCR。
- 当前评审调用保持一次性同步云函数请求，处理页只在本次小程序进程中保存状态，不承诺离线恢复。
- 模型组和模型 ID 由云函数环境变量配置，必须与目标云开发环境实际启用项一致。
