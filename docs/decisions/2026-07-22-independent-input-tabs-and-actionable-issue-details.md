# 材料 Tab 独立，问题详情改为可执行阅读

## 背景

文件解析正文与手动粘贴文本曾共用一个客户端字段，导致上传文件后正文自动出现在粘贴框中，也无法可靠表达用户最后选择的材料来源。报告问题卡同时堆放证据、诊断、影响、建议和标准，信息虽全但阅读密度过高；修改建议偏短，用户看完仍可能追问具体怎么改。

## 决定

1. “上传文件”和“粘贴文本”保存两份独立内容，切换 Tab 不清空也不互相回填。
2. 提交评审时，当前选中的 Tab 是唯一材料来源；即使另一个 Tab 有内容，当前 Tab 为空、过短或文件未解析完成时仍需拦截。
3. 文件解析成功态只展示文件名称、大小和格式；解析正文仅保存在本次客户端内存中用于提交，不在上传卡或文本框展示。
4. 问题卡默认展示优先级、问题标题、关键原文和领导结论；展开后按“影响—具体改法—通过标准”三个视觉层级阅读。
5. 每条修改建议必须给出 2-4 步执行顺序、应补字段或可套用句式；每条通过标准必须提供两项以上客观检查条件。模型输出过短时视为无效并触发重建。

## 影响

客户端输入状态、提交前校验、报告页视觉层级、报告 JSON Schema 最小长度、AI 生成规则、固定样例和真机验收步骤同步调整。云函数隐私协议、原文件删除策略和报告字段名称保持不变。
