# 正式客户端只保留真实评审链路

## 背景

早期小程序为了低成本验收界面，内置了反面材料填充、三档固定报告、开发工具脱敏文件和故障模拟入口。产品进入 `1.0.0` 正式发布阶段后，这些入口会让用户误以为评审结果可能是预设内容，也会增加小程序包体和无关运行分支。

## 决定

正式客户端只接受用户主动提交的文本或 PDF/DOCX，并统一调用微信云开发 `bml-api-v2` 完成解析与 AI 评审。移除所有样例填充、固定报告、模拟进度、故障模拟和开发工具专用文件入口。

角色详情页仍可展示静态好坏判词，用于说明角色的判断标准；它们不接受点击、不创建任务，也不生成报告。脱敏材料和质量档位报告继续作为自动化测试资产，统一放在 `tests/fixtures/`，不进入小程序生产包。

## 理由

- 正式版用户看到的每份报告都应能明确追溯到本次提交的材料。
- 删除模拟分支可以避免假报告被路由参数意外打开。
- 测试资产移出 `apps/miniprogram/` 后不会增加生产包体。
- 真实失败态和重试仍保留，继续覆盖云函数或网络异常。

## 未采用方案

- 仅在界面隐藏模拟按钮：路由参数仍可触发模拟报告，发布边界不够可靠。
- 保留开发者工具样例：会继续把测试 PDF 打进生产包，且正式验收与真机行为不一致。
- 模型失败后回退固定报告：无法保证报告引用用户原文，违背证据约束。

## 影响

- 微信开发者工具不再提供一键样例，发布验收需使用测试者准备的非敏感材料。
- 自动化测试继续使用离线固定报告，不产生模型费用。
- 生产客户端没有无模型费用的演示或降级路径；真实评审失败时展示可重试失败态，不伪造成功报告。
